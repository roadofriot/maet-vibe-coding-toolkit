# Skill 04: PRD & BRD Requirements Engineering
**Trigger:** Turning a raw idea or business need into a formal Product/Business Requirements Document.
## Workflow
1. Define **Problem Statement, Target Users, Core Value Proposition, and Success Metrics (KPIs)**.
2. Map **User Roles & Permissions Matrix** (e.g., Admin, Instructor, Student, Parent, Guest).
3. Specify **Functional Requirements** (User Stories + Explicit Acceptance Criteria).
4. Specify **Non-Functional Requirements** (Offline capability, response time under 200ms, low RAM usage, security, localization).
5. Explicitly list **Out of Scope / Phase 2** items to prevent scope creep.
